# Agent Settings

## Project context
- Control firmware for a hexapod robot.
- STM32F4 (Nucleo F401) firmware using HAL + FreeRTOS.
- Servo control via Dynamixel XL430 over half-duplex UART DMA.
- Key logic lives in `Core/Src/main.c`
- Servo related logic lives in `Core/Src/servos.c`
- The motion controller logic lives in `Core/Src/controller.c`

## Build and debug
- Primary build system: CMake + STM32Cube-generated sources.
- Typical local build dir: `cmake-build-debug`.
- Do not run hardware-dependent tests or flash unless asked.

## Coding conventions
- Use C99 and keep code compatible with embedded targets.
- Prefer `float32_t` and CMSIS-DSP functions where possible.
- Separate logic into functions and separate files where possible.
- Organize functions into logical groups and files.
- Avoid large refactors; keep changes minimal and localized.
- Prefer CMSIS-OS version 2 functions over FreeRTOS.

## Optimization
- Use `static` where possible.
- Timing is critical, profile and optimize.

## Concurrency and safety
- Shared state between tasks must be accessed via helper functions using critical sections.
- Do not read or write `servo_shared_state` directly outside helpers.
- Avoid torn reads/writes; snapshot before multi-step computations.

## Logging
- Use `LOG_ERROR`/`LOG_WARN` macros for runtime issues.
- Avoid excessive logging in tight loops.

## Files to avoid
- Do not modify autogenerated CubeMX regions unless necessary.
- Avoid touching `Drivers/` and `Middlewares/` or ask before doing so.

## Dependencies
- Dependencies are managed via Cmake.
- Dependencies are downloaded automatically during the first build.
- Dependencies are located in the build directory in the _deps directory.
- Changes to the hexapodmath and dynamixel dependencies can be proposed to the user.
